# แบบข้อเสนอโครงงาน

## ระบบจัดการร้านอาหาร [Restaurant Management System]

## สมาชิก

1. พัฒนเดช มะหิเมือง 6730300850
2. ธนภัทร คงแก้ว 6730300205

## รายละเอียดโดยย่อ

**คำแนะนำ**

- โครงงานนี้เป็นระบบจัดการร้านอาหาร [Restaurant Management System] มีวัตถุประสงค์เพื่อให้ผู้ดูแลร้านมีสะดวกในหลายๆด้านเช่น ดูประวัติการขายได้ รายได้ต่อวันขาดทุนกำไร ปรับปรุงแก้ไข เมณูของร้านที่มีอยู่ในปัจจุบัน สะดวกต่อผู้ใช้สามารถสั่งได้เลยพร้อมบอกรายละเอียดเพิ่มเตืม บางครั้งอาจมีคนเยอะทำให้พนักงานไม่พอ

## คุณลักษณะและขอบเขต

### คุณลักษณะขั้นต่ำ

- ระบบจัดการเมนู(การเพิ่ม,แก้ไข,หรือลบเมนูอาหาร) 
- ระบบรับออเดอร์(สั่งจากUI) 
- ระบบคำนวนยอดขาย(แสดงยอดขายรายวัน)
- ระบบบันทึกและโหลดออเดอร์(CSV/JSON)

**ตัวอย่างการเขียนสำหรับ Online Product Management**

- เป็นโปรแกรมจัดการสินค้าออนไลน์ โดยข้อมูลสินค้าจะประกอบด้วย ชื่อสินค้า รายละเอียด และราคา
- ผู้ใช้สามารถเพิ่ม แก้ไข และลบข้อมูลสินค้าได้
- มีหน้าจอใช้งานหลักซึ่งแสดงรายการสินค้าทั้งหมด และหน้าจอจัดการข้อมูลสำหรับเพิ่มหรือแก้ไขรายละเอียดสินค้า
- สามารถบันทึกข้อมูลสินค้าในรูปแบบ CSV หรือ JSON และสามารถเปิดไฟล์ข้อมูลขึ้นมาดูและแก้ไขในภายหลังได้


### คุณลักษณะเพิ่มเติม
- ระบบจัดการโต๊ะ 
 ลูกค้าสามารถเลือกโต๊ะได้
 แยกออเดอร์ตามโต๊ะ
- ระบบพิมพ์ใบเสร็จ
 ออกใบเสร็จให้ลูกค้าเป็นPDF
-ระบบสต๊อกวัตถุดิบ
 คำนวนวัตถุดิบคงเหลือ
 แจ้งเตือนเมนูที่หมดสต๊อก

## แผนการดำเนินโครงงาน

ร่างแผนการดำเนินโครงงานในระยะเวลา 2 เดือน (8 สัปดาห์) โดยระบุผลลัพธ์ที่คาดหวังว่าจะทำได้เสร็จในแต่ละระยะ เช่น

| **ระยะ**        | **ช่วงเวลา**   | **ผลลัพธ์ที่คาดหวัง**                                                                            |
| --------------- | -------------- | ------------------------------------------------------------------------------------------------ |
| เริ่มต้นโครงงาน | สัปดาห์ที่ 1-2 | - ส่งข้อเสนอโครงงาน<br>- สร้าง GitHub repository<br>- สร้างโครงงานด้วย Maven และเขียนโค้ดตั้งต้น |
| สร้างต้นแบบ     | สัปดาห์ที่ 3-4 | - โปรแกรม/ทำงานได้ในเบื้องต้น<br>- มีฟีเจอร์หลัก (core feature) ที่ใช้งานได้                  |
| ทดลองใช้งาน     | สัปดาห์ที่ 5-6 | - ฟีเจอร์ส่วนใหญ่พร้อมใช้งาน<br>- โปรแกรมสามารถใช้งานได้ แต่อาจต้องปรับแก้หรือเพิ่มเติม          |
| พร้อมส่งมอบงาน  | สัปดาห์ที่ 7-8 | - โปรแกรม/มีฟีเจอร์ครบถ้วนตามที่วางแผน<br>- เอกสารประกอบสมบูรณ์ พร้อมสำหรับการนำเสนอ          |
**หมายเหตุ**

- ฟีเจอร์หลัก (core feature) หมายถึงฟีเจอร์สำคัญที่ทำให้โปรแกรม/บรรลุวัตถุประสงค์หลัก
- MVP (Minimum Viable Product) คือเป้าหมายขั้นต่ำที่สามารถส่งมอบได้ อย่างไรก็ตาม ฟีเจอร์หลักอาจเป็น subset ของ MVP ได้ในบางกรณี

## การแบ่งงาน

ระบุแผนการแบ่งความรับผิดชอบของสมาชิกแต่ละคนในการทำโครงงาน ทั้งนี้ สมาชิกทุกคนต้องมีส่วนร่วมในการเขียนโค้ด เช่น

- **พัฒนเดช มะหิเมือง 1**:
	- ออกแบบ UI
	- เขียนโค้ดส่วนติดต่อผู้ใช้
	- จัดการ GitHub repository
- **ธนภัทร คงแก้ว 2**:
	- เขียนโค้ดส่วนจัดการข้อมูล
	- ทดสอบระบบ
	- ทำเอกสาร

## ความท้าทายและความเสี่ยง

1. **ความท้าทายด้านเทคนิค**:
    - ยังไม่คุ้นเคยกับ JavaFX ในการทำ GUI มาก่อน เนื่องจาก JavaFX เป็นเครื่องมือใหม่สำหรับการพัฒนา อาจต้องใช้เวลาในการศึกษาและทดลองเพิ่มเติม
    - **แนวทางแก้ไข**: ศึกษาตัวอย่างและบทเรียนจากลิงก์ Pragmatic Coding (https://www.pragmaticcoding.ca/beginners/intro)และ ศึกษาเอกสารจาก JavaFX Documentation
2. **ความท้าทายด้านการจัดการเวลา**:
    - สมาชิกมีเวลาจำกัดในการทำโครงงาน
    - เนื่องจากเป็นนักศึกษาที่มีวิชาเรียนอื่นๆ อาจทำให้มีเวลาพัฒนาระบบน้อย
    - **แนวทางแก้ไข**:กำหนดตารางเวลาการทำงานอย่างชัดเจน แบ่งงานกันทำและใช้ GitHub ในการจัดการโค้ด ติดตามความคืบหน้าของโครงการทุกสัปดาห์
3. **ความเสี่ยงที่อาจเกิดขึ้น**:
    - 	ระบบมีข้อผิดพลาดหรืออาจมีบั๊กในระบบ เช่น ข้อมูลไม่ถูกบันทึก หรือ UI แสดงผลผิดพลาด
    - **แนวทางแก้ไข**: ทดสอบระบบในทุกฟีเจอร์หลังจากพัฒนาเสร็จแต่ละส่วน ใช้ JUnit ในการทดสอบโค้ดที่เกี่ยวกับการจัดการข้อมูล

## ต้นแบบและเอกสารอ้างอิง
- ต้นแบบของระบบ (Prototype)
เพื่อให้การพัฒนาโครงงานเป็นไปตามแผนที่กำหนด เราได้ทำการออกแบบ ต้นแบบ UI (Prototype) ของระบบจัดการร้านอาหารโดยใช้ Figma (หรือซอฟต์แวร์ออกแบบอื่นๆ) ซึ่งแสดงให้เห็นถึงโครงสร้างหน้าจอของระบบ เช่น

หน้าสั่งอาหาร (Order Page) – ให้ลูกค้าสามารถเลือกเมนูและเพิ่มลงในออเดอร์
หน้าการจัดการเมนู (Menu Management) – สำหรับเพิ่ม, แก้ไข หรือ ลบรายการอาหาร
